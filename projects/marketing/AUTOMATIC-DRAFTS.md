# Automatic brand drafts

The Marketing Agent can run without a daily prompt or an open browser. The brand owner opts in once with **Start automatic drafts**, selecting 1–3 drafts per day (default: two, about twelve hours apart). Pausing stops new work. Existing manual drafting and live research remain optional assignments below the automatic dashboard.

The Hostinger Node process checks for work every minute, beginning ten seconds after startup. It signs an HTTPS request to the canonical application origin with a short-lived HMAC. This works when Hostinger provides a Unix socket rather than a TCP listening port. Express, Next proxy, and the route validate the exact worker route; the signature cannot open other private pages. All other authentication and origin requirements remain intact.

A per-brand private hash authenticates narrow database worker RPCs. The worker key is HKDF-derived from existing server encryption material, owner identity and canonical origin; it is never stored in the database or sent to the browser. No Supabase service-role key or persistent owner login token is needed. Only the brand owner may enable or reconfigure the worker. If the encryption root or owner changes, save the agent settings again to re-register the current hash.

The worker claims one due brand under a database row lock, advances its next run, and creates a ten-minute lease. It checks core brand purpose, audience, voice, unresolved conflicts and context size before reserving budget or calling OpenAI. Missing factual references do not block private evergreen drafts; gaps are recorded for review and never count as verified evidence. Each run reserves at most $0.03 within the existing shared $15 monthly application cap. A planner chooses an angle and channel from brand context and recent content, a writer drafts it, and the existing independent review pass checks claims and voice. Duplicate copy is skipped. Five outstanding agent drafts block further generation. Every outcome is visible in Agent activity.

Drafts keep NEEDS_REVIEW, UNVERIFIED, human approval and unsatisfied media flags. Nothing is automatically approved, scheduled or published. Routine runs use verified brand knowledge and evergreen angles; live news research and media production are not included. The optional daily briefing still performs live research on request.

Run and budget completion are atomic. Successful completion is idempotent. Expired runs are marked interrupted, any reservation is conservatively charged, and the same paid generation is not automatically retried. On restart, missed intervals yield one due run, not a catch-up burst. Runs depend on the hosting process being available; multiple processes are protected by database claims, but all must share the same server configuration.

Apply `supabase/migrations/20261118150000_autonomous_draft_agent.sql` before deploying. New brands remain paused until owner opt-in. Use the live UI to start; no raw secret setup is required. Tests cover HMAC boundaries, tenant isolation, leases, repeated reservations, atomic result persistence, budget denial, missing knowledge, duplicates and generation failures.
